四类模型优缺点总结：
BERT (Fine-tuning)	
    优点
        1. 精度高： 利用强大的上下文理解能力，在复杂、多样化的表达上准确率最高。
        2. 泛化能力强： 能很好地处理没见过的同义表达、俚语和略微复杂的句式。
        3. 端到端： 自动提取特征，无需繁琐的特征工程。	
    缺点：
        1. 资源消耗大： 训练和推理需要GPU，计算成本高，延迟相对最高。
        2. 数据依赖强： 需要大量高质量的标注数据才能达到最佳性能。
        3. 可解释性差： 模型决策过程像一个“黑盒”，难以调试。	
    总结：
        作为核心主力模型，处理大部分非结构化、口语化的用户输入。例如：“哥们儿，这车里太热了，快想想办法”、“我好像迷路了，能不能给我指条明路？”
Prompt Learning	
    优点：
        1. 小样本学习： 在标注数据极少的情况下，通过设计合适的提示（Prompt），能激发出预训练模型的大量知识，快速获得不错的效果。
        2. 灵活性强： 通过修改Prompt即可适应新的任务，无需重新训练模型。
        3. 与人类直觉接近： 任务被构造成“完形填空”，更符合人类思考方式。	
    缺点：
        1. 性能不稳定： 效果极度依赖于Prompt的设计，需要大量的尝试和调优（Prompt Engineering）。
        2. 推理速度慢： 与BERT类似，需要大模型进行推理，延迟高。
        3. 难以掌控： 可能会产生意想不到的预测结果。	
    总结：
        作为BERT的补充，特别适用于新增意图或标注数据非常少的冷启动场景。可以先用它快速上线，同时积累数据用于微调BERT。
TF-IDF + 机器学习 (如SVM)	
    优点：
        1. 速度快： 训练和推理速度极快，计算成本低，延迟低。
        2. 可解释性较好： 可以查看哪些关键词对分类贡献最大，便于调试和优化。
        3. 数据需求少： 在小规模数据上也能训练出一个可用的基线模型。
        4. 非常稳定。	
    缺点：
        1. 精度有限： 无法理解上下文和语义，性能天花板低。例如无法区分“把温度调高”和“这里高楼很多”。
        2. 特征工程复杂： 需要手动处理N-gram、停用词等。
        3. 泛化能力弱： 对未在训练集中出现的表达方式处理能力差。	
    总结：
        作为快速过滤器或处理简单、规范的查询。例如非常明确的指令：“打开空调”、“导航到北京西站”。可以作为第一层模型，快速处理掉大量简单请求，减轻BERT模型的负担。
正则表达式 (Regex Rule)	
    优点：
        1. 速度极快： 几乎是零延迟，计算开销可忽略不计。
        2. 100%准确： 一旦模式匹配，结果绝对可靠，不存在置信度问题。
        3. 完全可控： 规则由开发者完全定义，行为可预测，易于调试和维护。	
    缺点：
        1. 召回率极低： 只能匹配预设的模式，无法处理任何变化和泛化。
        2. 维护成本高： 需要持续维护和添加大量规则，难以扩展。
        3. 无法处理语义。	
    总结：
        处理非常核心、固定的表达方式，通常用于关键任务或高优先级意图。例如：“救命”、“拨打急救电话”、“车辆冒烟了”。确保这些关键意图在任何情况下都能被100%触发。
